配套实验：8.1 资产识别与 CIA 赋值 · 场景：优品商城电商交易系统（素材 4）· 对应步骤 1–5

步骤 1读场景，先画架构

三层关系：业务（交易）→ 系统（商城平台）→ 组件（服务器 / 数据库 / 接口 / 人）。画图的作用是回答一句话：这项资产到底撑着哪个业务。

资产 → 业务的对应关系（口语版，课堂上照着讲）

资产所在层直接支撑的业务怎么撑的
A-01 用户数据库数据层注册 / 登录存账号、手机号、密码哈希——没有它没人能登录
A-02 商品信息库数据层商品浏览 / 搜索存商品名、价格、库存、描述——浏览搜的就是它
A-03 订单数据数据层下单购买、在线支付、订单查询（3 项）订单号、金额、状态贯穿交易全流程，业务价值密度最高
A-04 支付接口应用层在线支付对接支付宝 / 微信，支付动作的出口
A-05 Web 服务器Web 层全部业务（入口）所有用户请求先进这里，2 台负载均衡
A-06 应用服务器应用层全部业务（逻辑）注册校验、下单扣库存等逻辑都在它上面跑
A-07 数据库服务器数据层全部业务（承载数据）A-01 / 02 / 03 三个库都放在它上面
A-08 防火墙互联网边界全部业务（安全前提）边界防护——它断了，五项业务外面都进不来
A-09 跳板机运维通道不直接面向业务运维人员唯一管理入口，保障系统持续运转
A-10 系统配置文件文档全部业务（运行支撑）含数据库连接信息、密钥——它泄露，上面全裸奔
三句话记住：① 业务不悬空，每项业务都能往下指到资产；② A-03 一项撑 3 项业务，是赋值最该打高的数据资产；③ 灰色资产是“共同命脉”，任何一台出问题，五项业务一起受影响——这正是它们可用性打高的原因。

编号资产名称类别所属层说明（照素材 4）
A-01用户数据库数据数据层含姓名、手机号、地址、密码哈希
A-02商品信息库数据数据层含商品名称、价格、库存、描述
A-03订单数据数据数据层含订单号、用户 ID、商品、金额、状态
A-04支付接口软件应用层对接支付宝 / 微信支付
A-05Web 服务器硬件Web 层2 台，运行 Tomcat
A-06应用服务器硬件应用层2 台，运行 Java 应用
A-07数据库服务器硬件数据层2 台（主从），运行 MySQL
A-08防火墙硬件互联网边界边界防护
A-09跳板机硬件运维通道运维管理入口
A-10系统配置文件文档运维通道含数据库连接信息、密钥等
四个最容易被扣分的点：
  • 数据 ≠ 服务器。A-01 用户数据库（数据）和 A-07 数据库服务器（硬件）是两项资产，一个被偷走、一个被宕机，后果完全不同。
  • 支付接口是“软件”不是“数据”。它本身是程序逻辑；它流转的金额、订单号属于 A-03 订单数据。
  • 配置文件是“文档”。很多人只列硬件和软件，把它漏掉——而它恰恰含密钥，是后面唯一一个 C 打 5 的非数据库资产。
  • 编号别重排。素材 4 的 A-01～A-10 是后面实验、威胁与脆弱性编号的对齐基准，改了会全乱。

步骤 3逐项 CIA 赋值，写依据

三句话定档：泄露了损失多大（C）？被篡改了后果多严重（I）？宕机了影响多大（A）？照素材 1 速查卡或素材 3 的 GB/T 20984 赋值表对档，每个分值后面必须有一句业务影响依据。

资产C（保密性）与依据I（完整性）与依据 A（可用性）与依据
A-01 用户数据库5｜姓名+手机号+地址+密码哈希，泄露可被精准诈骗、撞库，并触发监管处罚5｜篡改余额或收货地址会导致错发、漏发与纠纷，且难以追溯弥补4｜短时可离线（允许中断 < 10 分钟），但登录会全面受阻
A-02 商品信息库2｜商品信息本身就是公开可查的4｜改价、改库存直接造成错单与交易纠纷，损失较难弥补3｜可降级为静态页面，允许中断 < 30 分钟
A-03 订单数据4｜含用户 ID、金额、收货地址，属重要交易信息5｜金额与状态被篡改，账务无法追溯，无法接受4｜下单短时排队可容忍，中断 < 10 分钟
A-04 支付接口4｜涉及支付凭证与签名密钥5｜改金额、改收款方即直接资金损失5｜支付不允许中断，中断即刻丢单
A-05 Web 服务器2｜本身不存敏感数据（配置另算 A-10）3｜页面或配置被改，影响明显但可从备份恢复5｜全站入口，2 台全宕则五项业务都访问不了
A-06 应用服务器3｜运行时内存中有用户数据，日志可能留痕4｜业务逻辑被篡改会导致大范围错单，较难弥补5｜所有业务逻辑在此运行，不允许中断
A-07 数据库服务器4｜承载三个库，权限最高，被控等于全库失守5｜数据载体被破坏，全库数据不可信5｜虽有主从，仍属数据层命脉，不允许中断
A-08 防火墙2｜策略本身敏感度低3｜策略被改会端口暴露或误阻断，可恢复5｜边界失效，全站暴露或全站不可达
A-09 跳板机4｜含运维账号与内网拓扑，泄露等于交出内网地图4｜被控后可横向移动到全部服务器3｜短时不可用可由本地应急通道替代，< 30 分钟
A-10 系统配置文件5｜含数据库连接串与密钥，泄露等于拿到库钥匙4｜篡改后应用连错库或被指向攻击者，影响严重2｜有备份与模板可重建，允许中断 < 1 小时
三个“为什么这样打”的典型问题：
  • 为什么 A-01 的 A 不是 5？数据库宕机时，已登录用户仍可浏览商品、下单可先入队列，业务能短时降级——所以按速查卡落在“允许中断 < 10 分钟”的 4 档。
  • 为什么 A-10 配置文件 C 打 5、A 只打 2？它泄密的后果最重（直接交出数据库钥匙），但它随时可从备份或模板重建，缺失的可用性影响相对小。
  • 为什么 A-05 Web 服务器 C 只有 2？它只是请求入口，不落敏感数据；敏感数据在 A-01/02/03 里——资产边界划清，赋值才不会串味。

步骤 4算价值，标关键资产

公式：资产价值 =（C + I + A）÷ 3，保留 1 位小数；价值 ≥ 4 标为关键资产。价值必须能由三个分值复算出来，不能“感觉重要给个 4.5”。

编号资产名称CIA计算资产价值关键性说明
A-01用户数据库554(5+5+4)/34.7 关键登录的唯一凭据源，出事全站用户受影响
A-04支付接口455(4+5+5)/34.7 关键资金出口，中断即丢单，篡改即丢钱
A-07数据库服务器455(4+5+5)/34.7 关键三个库的载体，数据层单点命脉
A-03订单数据454(4+5+4)/34.3 关键一项撑下单、支付、查询三条业务
A-06应用服务器345(3+4+5)/34.0 关键全部业务逻辑在此运行，宕机即全停
A-09跳板机443(4+4+3)/33.7管理入口，权限高但非直接业务资产
A-10系统配置文件542(5+4+2)/33.7分值不低但单项偏低，价值排序靠后——别只看 C
A-05Web 服务器235(2+3+5)/33.3入口，可用性极高但机密性低

编号资产名称价值一句话理由（写进关键性说明）
A-01用户数据库4.7登录凭据的唯一样本来源，泄露涉个人信息合规责任，篡改导致错单

为什么 A-10 配置文件 C 打了 5 却不是关键资产？因为价值是三维平均：它的 A 只有 2（可重建），把均值拉到 3.7。这正好说明“单项高 ≠ 关键资产”——但要注意：价值不到 4 不等于可以不管，它在后续威胁分析里往往是被攻击的跳板，威胁值会很高。

分歧点打高的理由打低的理由
A-05 Web 服务器
A = 5 还是 4？		按“整体服务”评：入口不可用 = 全站不可访问，给 5按“单台”评：2 台负载均衡，单台宕机业务不受影响，给 4

评分口径：分歧本身不扣分，没依据才扣分。只要备注里写清“我是按整体还是按单台评的”，两种口径都给分；答辩时说得出依据，比分数对不对更重要。

交之前最后看一眼：有没有出现“所有资产都打 3 分”“按服务器采购价赋值”“只列硬件软件、漏掉数据和文档”这三种典型错——只要中一条，整张表在后面的风险计算里就失效了。
